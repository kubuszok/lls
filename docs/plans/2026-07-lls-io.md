## 1. Context a weak model lacks

### 1.1 Why

Path/file logic is duplicated across two repos with different designs:

- **ssg** (`ssg-commons/src/main/scala/ssg/commons/io/{FilePath,FileOps}.scala` + three platform
  impl pairs under `ssg-commons/src/main/{scalajvm,scalajs,scalanative}/ssg/commons/io/`): an
  **immutable POSIX-string** `FilePath` (forward slashes on every OS, Windows drive letters
  rendered `/C:/x`) plus a `FileOps` object with deterministic ordering guarantees and
  documented symlink rules. ~1,100 lines, heavily covenant/ISS-tested. This is the design being
  promoted.
- **sge** (`sge/src/main/scala/sge/files/FileHandles.scala`, 712 lines, + `FileType.scala`,
  `Files.scala`, desktop/browser/android impls): a mutable `java.io.File`-centric `FileHandle`
  ported from libGDX. **This is port-covenant surface and is NOT replaced or altered** (§8).

The shared code moves to a new **published artifact `lls-io`** in the lls repo (namespace
`lowlevel.io`), because lls already hosts the shared `lowlevel.*` types both repos consume, has
a working release pipeline (tag → `sbt ci-release`), and a Windows CI matrix that ssg lacks.

### 1.2 What "done" means

1. lls publishes `com.kubuszok %% lls-io % 0.3.0` for JVM, Scala.js, Scala Native (Scala 3),
   with the API in §3, the semantics in §4 (including the UNC fix and drive-root normalize
   floor), and the test suites in §7 green on the full lls CI matrix (including Windows JVM).
2. ssg's `ssg.commons.io` package is reduced to a deprecated re-export shim (§6); all internal
   ssg call sites import `lowlevel.io` directly; ssg CI fully green on all three platforms.
3. sge records the delegation-verdict table (§8) in its docs and bumps its lls pin in lockstep;
   `FileHandle` behavior is byte-identical (proven by the existing covenant suite).

### 1.3 What must NOT change

- **sge `FileHandle` public behavior** — it is `Covenant: full-port` surface
  (`sge/src/main/scala/sge/files/FileHandles.scala:21-28`). No signature, no observable
  behavior (including error types and symlink-following semantics) may change. §8 proves most
  internals must therefore keep their current bodies.
- **lls core (`lls` artifact) stays zero-dependency**, and `lls-io` itself is also
  zero-dependency (it does not even depend on `lls` core — nothing there is needed). MiMa
  guards `lls` core: no core source file is touched by this plan.
- **ssg observable path semantics** for everything already pinned by its ISS suites
  (ISS-977/978/980/982/1121/1123/1127/1128/1182/1346/1347). The only intentional behavior
  changes are the two latent-bug fixes in §4.4/§4.5, each of which gets a pinned test.
- **Ordering guarantees** of `list`/`walkTree` (sorted by path string, pre-order) — ssg's
  golden-output pipeline (`ssg-site/src/test/scalajvm/ssg/site/SitePipelineGoldenSuite.scala`)
  depends on them.

### 1.4 Sequencing constraint (hard)

## 3. `lls-io` public API (exact)

Package: `lowlevel.io` (split-package style `package lowlevel` / `package io`, matching
`lowlevel.*` convention). Artifact: `com.kubuszok %% lls-io`.

### 3.1 `FilePath` — one shared final class (not a trait, not an opaque type)

Design decisions, with reasons the implementer must not re-litigate:

- **Final class, single shared implementation.** All three ssg impls already hold a plain
  string with pure string ops; only `cwd` and the I/O bridge are platform-specific. Unifying
  removes the per-platform-class `equals` quirk (ssg's `JvmFilePath.equals` only matches
  `JvmFilePath`) — `lls-io` equality is plain `pathString` equality.
- **Not a trait**: nothing subclasses ssg's `FilePath` outside its own package (verified §2),
  and a sealed hierarchy buys nothing once the implementation is shared.
- **Not an opaque type over `String`**: the overloads `resolve(String)` and `resolve(FilePath)`
  would erase to the same `(String)String` signature and fail to compile. A final class keeps
  ssg's exact call-site shape.
- **`normalize` uses the pure resolver on ALL platforms** (promoted from ssg's Native impl).
  This removes the JVM's nio-normalize delegation, which is host-dependent for drive-absolute
  paths (§4.5) — a latent ssg bug this plan fixes.

```scala
package lowlevel
package io

/** Immutable, OS-independent file path in POSIX string form ('/'-separated on every OS;
  * Windows drive-absolute paths are modelled as "/C:/x", UNC paths as "//host/share/x"). */
final class FilePath private[io] (val pathString: String) {
  def parent: Option[FilePath]
  def resolve(other: String): FilePath
  def resolve(other: FilePath): FilePath
  def fileName: String
  def isAbsolute: Boolean
  def toAbsolute: FilePath
  def normalize: FilePath
  override def toString: String            // = pathString
  override def equals(obj: Any): Boolean   // pathString equality vs any FilePath
  override def hashCode: Int               // = pathString.hashCode
}

object FilePath {
  /** The model separator. Always '/': the model is POSIX-string on every OS. */
  val separatorChar: Char = '/'
  def of(path: String): FilePath   // renders per §4.1, shared pure code
  def cwd: FilePath                // platform-provided host cwd in model form (§5)
}
```

`parent` returns `Option` (not `lowlevel.Nullable`) deliberately: it matches the ssg call-site
shape 1:1 so migration is import-swapping, and taking `Nullable` would create a dependency on
`lls` core, which §1.3 forbids.

### 3.2 `FileOps` — exactly ssg's proven surface, nothing more

The v1 surface is **identical to** `ssg-commons/.../io/FileOps.scala` (that surface is
covenant-verified and fully test-pinned; additions such as a `size` operation are future minor
releases, not this plan):

```scala
package lowlevel
package io

import java.nio.charset.Charset

object FileOps {
  def readAllBytes(path: FilePath): Array[Byte]
  def readString(path: FilePath): String                    // UTF-8
  def readString(path: FilePath, charset: Charset): String
  def writeBytes(path: FilePath, bytes: Array[Byte]): Unit
  def writeString(path: FilePath, content: String): Unit    // UTF-8
  def writeString(path: FilePath, content: String, charset: Charset): Unit
  def exists(path: FilePath): Boolean
  def isDirectory(path: FilePath): Boolean
  def isRegularFile(path: FilePath): Boolean
  def lastModifiedTime(path: FilePath): Long                // epoch millis; throws on missing
  def list(path: FilePath): List[FilePath]                  // sorted; throws on missing/non-dir
  def walkTree(path: FilePath): List[FilePath]              // pre-order, sorted per level; no symlink descent
  def createDirectories(path: FilePath): Unit               // idempotent
  def copy(from: FilePath, to: FilePath): Unit              // byte-exact, replaces existing
  def deleteRecursively(path: FilePath): Unit               // missing = no-op; never follows symlinks
  def isSupported: Boolean                                  // false only in a browser (no Node fs)
}
```

Scaladoc contracts are carried over verbatim from the ssg file (they encode the symlink,
ordering, and error contracts that the golden pipeline relies on), with `ssg`-specific
references (site-pipeline-design.md, ISS ids) rewritten as plain contract statements plus a
provenance line: `Origin: extracted from ssg ssg-commons/.../io/FileOps.scala (ISS-…)`.

### 3.3 `FilePathNio` — public nio bridge (JVM and Native only)

ssg-sass production code uses `FilePathPlatform.toNioPath/fromNioPath` today (§2), so the
bridge is public API, but only on platforms that have `java.nio.file`:

```scala
package lowlevel
package io

object FilePathNio {   // defined in src/main/scalajvm AND src/main/scalanative (identical bodies)
  def toNioPath(path: FilePath): java.nio.file.Path    // strips "/C:/x" -> "C:/x" (§4.3); UNC passes through (§4.4)
  def fromNioPath(path: java.nio.file.Path): FilePath  // POSIX-renders; restores "/" drive prefix; preserves UNC "//"
}
```

There is **no** JS `FilePathNio`. JS-only consumers keep using `pathString` directly (as ssg's
JS `FileOpsPlatform` does).

## 4. Path model semantics (normative spec)

### 4.1 Rendering (`FilePath.of`, and re-rendering inside `fromNioPath`)

Given input `p`:

1. Backslash `\` is a **legal filename character**, never a separator (ssg ISS-1128 contract).
   `of("a\\b").pathString == "a\\b"`.
2. Runs of `/` collapse to one, **except** a leading run of exactly two slashes followed by a
   non-slash character, which is preserved as the UNC marker (§4.4). A leading run of 3+
   slashes collapses to a single `/` (POSIX: only exactly-two is implementation-defined).
3. A trailing `/` is dropped unless the result is the root `/`.
4. `.` and `..` segments are **preserved** by rendering (resolution happens only in
   `normalize`), matching `java.nio` `Paths.get("a/../b").toString == "a/../b"`.

### 4.2 Core operations

Identical to ssg's current pinned behavior (the ISS-1127/980/982/1182 contracts):

- `isAbsolute` ⇔ `pathString.startsWith("/")` — a pure string predicate, uniform on every OS.
- `parent`: POSIX dirname mapped to `java.nio.getParent` semantics — `None` for the root, for a
  relative single segment, and (new) for a UNC root (§4.4); otherwise `Some(dirname)`.
- `resolve(other)`: empty child → `this`; child starting with `/` → the child **passed
  through `renderPath` first** (absolute replaces, like `java.nio.Path.resolve` — but the
  result must satisfy the every-`pathString`-is-rendered invariant, so `resolve("///a")`
  yields `/a`, and `resolve("//h//s")` yields `//h/s` keeping the UNC marker per §4.4).
  DEVIATION from ssg (which takes the child verbatim): ssg's verbatim behavior can produce
  non-canonical `pathString`s that break the `equals`/`normalize` invariants — this is a
  bug-fix-class deviation; pin it with a test asserting the two examples above; else append
  with a single `/`.
- `fileName`: POSIX basename; `""` for the root and (new) for a UNC root.
- `toAbsolute`: `this` if absolute, else `cwd.resolve(pathString)` — **no** normalization
  (matches `java.nio.toAbsolutePath`).
- `normalize`: the pure dot-segment resolver (ssg Native `posixNormalize`,
  `ssg-commons/src/main/scalanative/ssg/commons/io/FilePathPlatform.scala:125-159`) promoted to
  shared code, **extended with two floor rules** (§4.4, §4.5). Reduces-to-nothing → `""`
  (matching `Paths.get(".").normalize().toString == ""`).

### 4.3 Windows drive-letter model — KEEP ssg's `/C:/x` rendering

Decision: **keep**. Justification (record in scaladoc):

1. It preserves the invariant "absolute ⇔ leading `/`" as a pure string predicate identical on
   all platforms — the whole point of the POSIX-string model.
2. A bare `C:/x` rendering cannot work: `:` must remain a legal POSIX filename character
   (ISS-1128), so `C:/x` is indistinguishable from a relative path whose first segment is the
   file name `C:` — `isAbsolute` would become OS-dependent guesswork.
3. The form is already round-trip-proven on real Windows by ssg's CI
   (`FilePathWin32ParityIss1128Suite` et al.) via `toNioPath` (strip leading `/` when
   `isDriveAbsolute`) and `fromNioPath` (prefix `/` when the nio path is absolute but the
   rendered string is not).
4. Migration cost of keeping it is zero; changing it would invalidate ssg golden outputs.

Documented ambiguity (accept, do not "fix"): on POSIX, a real file `/C:/x` (directory literally
named `C:`) has the same model form as the Windows drive path. The ambiguity only affects the
nio bridge **on Windows**, where such POSIX names do not occur.

`isDriveAbsolute(p)`: `p.length >= 3 && p(0) == '/' && p(2) == ':' && p(1).isAsciiLetter`
(verbatim from ssg).

### 4.4 UNC paths — the latent ssg bug, and the specified behavior

**Current ssg bug (all three platforms):** `renderPath` collapses every duplicate separator, so
`FilePath.of("//server/share/x")` and — worse — `fromNioPath(Paths.get("\\\\server\\share\\x"))`
on Windows both yield `"/server/share/x"`. `toNioPath` then produces a **current-drive-rooted
local path** (`\server\share\x`) on Windows: file I/O is silently redirected to a wrong,
plausible-looking location. Additionally `cwd` on a UNC working directory degrades the same way
on the next re-render. This is a data-loss-class bug; S2 files it in ssg's issue DB with a
reference to this plan even though the fix ships via migration.

**Specified lls-io behavior** (POSIX allows exactly-two leading slashes to be
implementation-defined; we define it as the UNC marker, matching Windows nio and Node
`path.win32` root treatment):

| Rule | Spec |
|---|---|
| Model form | `//host/share/seg...` — exactly two leading slashes, then ordinary segments |
| `of` rendering | leading `//` + non-slash preserved; `///a` → `/a`; `//` alone → `/` |
| `of` drive-lift (ADDENDUM 2026-07-02, bug-fix-class deviation from ssg) | native Windows drive-absolute inputs are lifted into model form: `of("C:\\a")` → `/C:/a`, `of("C:/a")` → `/C:/a`, and `isAbsolute` is then true; without this, `toAbsolute` cwd-joins an absolute path (ssg ISS-1383 — 26 Windows CI failures). Pin both rows + a toAbsolute-non-joining assertion in the rendering suite. |
| `isUncAbsolute(p)` | `p.length >= 3 && p(0)=='/' && p(1)=='/' && p(2)!='/'` (private[io] helper) |
| Root component | `//host/share` when ≥2 segments exist; `//host` when only one. The root is its own floor. |
| `isAbsolute` | `true` (leading `/`) |
| `parent` | `parent("//h/s/x") == Some("//h/s")`; `parent("//h/s") == None`; `parent("//h") == None` |
| `fileName` | `fileName("//h/s/x") == "x"`; `fileName("//h/s") == ""`; `fileName("//h") == ""` (root ⇒ empty, like `/`) |
| `normalize` | `..` never rises above the UNC root: `normalize("//h/s/a/../..") == "//h/s"`; `normalize("//h/s/..") == "//h/s"`; single-segment floors likewise: `normalize("//h/..") == "//h"`; `normalize("//h/a/../..") == "//h"`; the `//` prefix is never lost. Pin all four in the UNC suite. |
| `resolve` | unchanged rules; an absolute child (leading `/`, including a `//...` child) replaces the UNC base |
| `toNioPath` | model form passes through **unchanged** (`Paths.get("//h/s/x")` parses as UNC on Windows; on POSIX the OS treats `//` as `/`, harmless) |
| `fromNioPath` (Windows) | `\\h\s\x` → backslash→slash → `//h/s/x`; the renderer's exactly-two rule preserves it |
| Equality | `/a` ≠ `//a` (distinct strings, distinct meanings) — documented |

Windows-execution caveat: lls CI has Windows **JVM** legs (§2) where the
`toNioPath`/`fromNioPath` UNC round-trip is asserted against real `java.nio` parsing
(string-level round-trip only — no actual network share is touched). The pure string rules are
asserted on every platform. Failure branch: if the implementer finds no Windows **Native** leg
in `lls/.github/workflows/ci.yml` (check with `grep -n windows .github/workflows/ci.yml`), the
Native UNC bridge test is tagged to run wherever the suite executes (pure string assertions
still run everywhere) and a follow-up lls issue "add windows native CI leg" is filed — do NOT
block the release on it.

### 4.5 Drive-root normalize floor (second latent ssg inconsistency, fixed)

ssg today: JVM `normalize` delegates to host nio, so `"/C:/a/../.."` normalizes to `"/C:"` on a
Windows host but `"/"` on a POSIX host (host-dependent output for the same model string); the
Native pure resolver's scaladoc claims the drive prefix is preserved but its code pops the `C:`
segment like any other (doc/code mismatch). lls-io specifies, host-independently:

- If the path is absolute and its first segment matches the drive pattern (`X:`), that segment
  is a **floor**: `..` cannot remove it. `normalize("/C:/a/../..") == "/C:"`,
  `normalize("/C:/..") == "/C:"`.
- Same rule for the UNC root (§4.4).
- Plain absolute paths keep POSIX behavior: `normalize("/a/../../..") == "/"`.

S2 files the ssg-side issue records for both §4.4 and §4.5 so the ssg history explains why
migrated behavior differs at these edges.

## 8. sge delegation analysis — verdict table

Covenant constraint: `FileHandle` (`sge/src/main/scala/sge/files/FileHandles.scala`) is a
libGDX full-port; **no observable behavior may change**, including error types, return-value
conventions (Boolean vs throw), symlink handling, and listing order. Additional structural
constraint discovered during grounding: `FileHandles.scala` is **shared source compiled for
Scala.js too**, against a linker-satisfaction `java.io.File` placeholder
(`sge/src/main/scalajs/java/io/File.scala`) — any base-class body change alters the JS-visible
failure mode of that code path.

| # | Site | Candidate delegation | Verdict | Reason |
|---|---|---|---|---|
| 1 | `FileHandles.scala:71` `path` | `FilePath.of(...).pathString` | **UNSAFE** | lls-io rendering collapses duplicate `/`; libGDX `getPath().replace('\\','/')` preserves them — observable output change |
| 2 | `FileHandles.scala:405,417,433,448` `list(...)` | `FileOps.list` | **UNSAFE** | libGDX returns unsorted `File.list()` order and empty array on missing/non-dir; `FileOps.list` sorts and throws — both observable |
| 3 | `FileHandles.scala:460` `isDirectory()` | `FileOps.isDirectory` | **UNSAFE in shared source** | semantics coincide on JVM/Native (follow-links, false-on-missing), but on JS the base-class failure mode changes from `UnsupportedOperationException` (File placeholder) to a Node `require` error; `FileHandles.scala` cannot be platform-split without restructuring covenant surface |
| 4 | `FileHandles.scala:496` `exists()` (non-classpath branch) | `FileOps.exists` | **UNSAFE in shared source** | same JS caveat as #3; on JVM/Native it is behavior-neutral but gains nothing functionally |
| 5 | `FileHandles.scala:487` `mkdirs()` | `FileOps.createDirectories` | **UNSAFE** | `File.mkdirs()` fails by returning false (ignored); `createDirectories` throws `IOException` — failure-path behavior change |
| 6 | `FileHandles.scala:520` `delete()` | — | **UNSAFE** | `File.delete()` returns Boolean and refuses non-empty dirs; no FileOps op has that contract |
| 7 | `FileHandles.scala:530,642` `deleteDirectory` / `:540,647` `emptyDirectory` | `FileOps.deleteRecursively` | **UNSAFE** | libGDX recurses via `File.isDirectory()` which FOLLOWS directory symlinks (deletes link targets' contents); `FileOps` never follows — observable (and covenant-pinned) difference |
| 8 | `FileHandles.scala:603` `lastModified()` | `FileOps.lastModifiedTime` | **UNSAFE** | `File.lastModified()` returns 0 for missing files; `lastModifiedTime` throws; an `exists()` guard adds a TOCTOU window |
| 9 | `FileHandles.scala:587` `length()` | — | **N/A** | no size operation in the v1 FileOps surface (deliberate, §3.2) |
| 10 | `FileHandles.scala:214,240` `readBytes` / `:193` `readString` / `:372,389` `writeBytes` | `FileOps.read*/write*` | **UNSAFE** | must route through `read()`/`write()` for Classpath/Internal resource fallback, append mode, and SgeError mapping |
| 11 | `DesktopFileHandle.scala:33,37,42,50` child/sibling/parent/file | `FilePath.resolve/parent` | **UNSAFE** | `java.io.File(parent, child)` arithmetic (separator handling, empty-parent, absolute-child) differs from POSIX-model resolve; outputs feed `path` (#1) |
| 12 | `AndroidFileHandle.scala:41-175` | — | **N/A / UNSAFE** | AssetManager-backed branches have no filesystem analogue; File-backed branches inherit #1–#8 verdicts |
| 13 | `BrowserFileHandle.scala:43-154` | — | **N/A** | browser has no fs; `FileOps.isSupported == false` there by design |

**Roadmap correction (record in the sge doc):** Topic 1's assumption that sge platform impls
would "delegate to lls-io for path arithmetic and raw I/O where semantics coincide" does not
survive enumeration — semantics coincide at exactly two sites (#3, #4), both blocked by the
shared-source JS caveat and yielding zero functional benefit. **Default posture: sge rewires
nothing inside `FileHandle`.** sge adopts lls-io as the standard library for NEW cross-platform
I/O code (tooling, resource pipelines, future `sge-build` needs) and bumps its lls pin in
lockstep with ssg. Issue G1 (§10) records this table in
`sge/docs/architecture/lls-io-delegation.md` so the decision is auditable and future sites get
vetted against it.
